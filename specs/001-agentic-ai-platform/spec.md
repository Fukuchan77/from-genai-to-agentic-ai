# agentic-ai-platform — Requirements

## Overview

LLM アプリ開発を Python / LangChain で学んだ（あるいは学ぼうとしている）エンジニアが、TypeScript / Web 標準スタックで本番品質の Agentic AI システムを一人で設計・構築・評価できるようになることを目的とする。本 spec は、マスターカリキュラム全4フェーズ・14モジュールに、他ドラフトから復元した5モジュールを加えた計19モジュールのハンズオンを「ローカルで動き、テストで検証できるリファレンス実装」と「モジュール別の日本語解説」として提供するプラットフォーム（以下「プラットフォーム」）の要件を定義する。価値は、(1) 受動的生成 → タスク自動化 → 自律型エージェントへの成熟段階をコードで体験できること、(2) API キーなしでも全テストが決定論的に通ること、(3) 各モジュールの習熟度をチェックリストと自動テストで客観判定できること、の3点にある。

カリキュラム全体の要件は、マイルストーン単位の4つの spec に分かれている（2026-09-27、Review C-1）。**本 spec（001）はプラットフォーム基盤と Milestone 1（Phase 1）を定義し、全 spec に共通する前提（用語集、技術制約、実行環境、LLM 実行モードとテスト方針、非機能要件、解説ドキュメントの枠組み）の正本を兼ねる。**

## Project Description

出典: [specs/drafts/Next-Gen AgenticAI App Dev Learning.md](../drafts/Next-Gen%20AgenticAI%20App%20Dev%20Learning.md)（マスターカリキュラム。他ドラフトと矛盾する場合はこちらを正とする）。マスターカリキュラムが統合時に落とした内容は、[`1_llm-agent.md`](../drafts/1_llm-agent.md)、[`2_ai-agent.md`](../drafts/2_ai-agent.md)、[`3_genai-agent.md`](../drafts/3_genai-agent.md)、[`Agentic AI Development Guide.md`](../drafts/Agentic%20AI%20Development%20Guide.md) から復元した（[ドラフトからの復元対応表](#ドラフトからの復元対応表)）。

Python / LangChain / LangGraph ベースの3冊の教材（AIアプリ開発入門、RAG・AIエージェント実践入門、AIエージェント実践入門）と Anthropic / IBM の Agentic AI 知見を、TypeScript / Next.js / Vercel AI SDK / Zod / MCP / E2B / Vitest のスタックへ移植・統合した、4フェーズ構成の学習カリキュラムおよびそのリファレンス実装。

- **Phase 1 基礎編**: 概念体系（生成 AI → AI Agents → Agentic AI）、モノレポ・Biome 基盤、AI SDK v7 Core（`generateText` / `streamText`、`Output.object` による構造化出力、`ToolLoopAgent` によるツール呼び出しループ）、マルチプロバイダ切替ストリーミングチャット（画像入力・ペルソナ切替）、Generative UI、Web 記事・YouTube 字幕の構造化要約、プロンプトキャッシュ
- **Phase 2 発展編**: TypeScript ネイティブ RAG（pgvector + Drizzle、引用付き回答、Agentic RAG）、Advanced RAG（HyDE / Multi-Query / RRF / Rerank、RAG 評価）、Anthropic 5大ワークフローパターン、エージェントデザインパターン（18 パターン体系と主要 6 実装）
- **Phase 3 現場実践編**: ACI 設計と MCP、ヘルプデスク（Plan-and-Execute）、データ分析（E2B サンドボックス + 自己修正）、階層型論文リサーチ（Agent-as-a-Tool）、要件定義書生成（インタビュー型）、マーケティング支援（ロールプレイ合議・会話型レコメンド）
- **Phase 4 運用・品質編**: コンテキストエンジニアリング（Compaction / Note-Taking / 段階的開示 / メモリ分類）、長時間実行2層ハーネス（Initializer → Worker）、Agent Evals（Vitest、LLM-as-a-Judge、合成データ、CI 統合）、安全設計（ブラスト半径、強制停止条件、Human-in-the-Loop、プロンプトインジェクション対策、OpenTelemetry）、総合演習（アーキテクチャ選定）

計画上のリポジトリ構成は pnpm + Turborepo モノレポ（`apps/web`、`packages/ai-core`、`packages/eval-suite`）。各フェーズにはハンズオン課題と習熟度判定チェックリストが定義されている。

## Technical Constraints

- バージョン方針: 各ライブラリは実装時点の最新安定版を採用し、`mise.toml` / `package.json` で固定する。ただし次世代志向として、Node.js v26（LTS 予定）と TypeScript v7.1（安定リリース前）を先行採用する
- TypeScript 7.1 先行版の方針:
  - 全ワークスペース（`apps/*`、`packages/*`、テスト用 tsconfig）で TypeScript 7.1 先行版を使うことを原則とする。
  - 先行版は範囲指定ではなく完全一致のバージョン（例: `7.1.0-dev.YYYYMMDD.N`）で固定し、公開から 24 時間以上経過したビルドだけを採用する（`pnpm-workspace.yaml` の `minimumReleaseAge` と整合させる）。
  - TypeScript 7 はネイティブ実装で JS コンパイラ API を持たないため、コンパイラ API に依存するツールは採用しない。同等機能を持つ代替ツールを優先する。
  - 先行版に起因する非互換で代替もない場合に限り、影響するツールまたはワークスペースだけを TypeScript 6.x 安定版へ後退させる。後退した範囲、理由、解除条件は `package.json` のコメントと解説ドキュメントに記録する。
  - 先行版の最新ビルドと正式版の公開状況を確認する手段（例: `mise run outdated`）を提供する。
- AI SDK 方針:
  - Vercel AI SDK v7 を使う。エージェントループは `ToolLoopAgent`（`instructions`、`tools`、`stopWhen: isStepCount(n)` 等）で実装する。構造化出力は `Output.object`、ツール入力は `inputSchema` で定義する。Human-in-the-Loop は呼び出し単位の `toolApproval` 機構を使う。
  - ワークフローパターン（002 Req 3）は、`ToolLoopAgent` を使わず素の TypeScript で制御フローを書く（ワークフローとエージェントの峻別を教えるため）。
- API とモデル ID は実装時点の公式ドキュメント（Context7 等）で検証したものを正とする。ドラフトのコード例（例: tool の `parameters`、`maxSteps`、`generateObject` / `streamObject`、`toDataStreamResponse()`、`experimental.reactCompiler`、`claude-3-7-sonnet` / `GPT-4o`）との差分は、モジュール解説に明記する
- Node v26、Next.js 等の先行版に起因するツールチェーン（Biome、Vitest、Next.js 等）の互換性問題の扱いは、設計フェーズで定める（TypeScript については上記の方針に従う）

## Runtime Environment

- 利用者: 学習者1人がローカル環境で実行する
- Postgres + pgvector、Langfuse（トレース）は Docker Compose でローカル起動する
- E2B（サンドボックス）、Cohere Rerank など API キー必須の外部サービスは、キーが設定されている場合のみ有効化し、未設定時はスキップまたは代替実装で動作を継続する
- 長時間実行ハーネスは、コンテナ（またはデータ分析エージェントと同じサンドボックス）内で実行する。コンテナ実行環境がない場合、ハーネスは起動しない
- 品質ゲートは Docker を必要としない。Docker Compose のサービスは、ハンズオンの実行と、品質ゲートとは別のタスクでだけ使う

## LLM Provider & Test Strategy

- LLM 実行モードは3層を切替可能にする:
  1. **モック**: AI SDK のテスト用モックモデルによる決定論的実行（API キー不要）。応答はシナリオスクリプトまたは録画したカセットの再生で供給する（Req 2.4、Req 2.13）。テスト専用で、ハンズオンでは明示的に指定した場合にのみ使う
  2. **ローカル LLM**: Ollama。Web アプリとハンズオンの既定の実行モード（Req 2.12）
  3. **実 API**: Anthropic / OpenAI / IBM watsonx.ai / Microsoft Azure（Azure OpenAI）/ Google を設定で切替。IBM watsonx.ai は、AI SDK v7 に対応したプロバイダ実装が存在する場合に限り提供し、存在しない場合はスキップする（2026-09 時点の `watsonx-ai-provider` 2.x は AI SDK v6 対象。v7 対応は設計フェーズで実測確認する）
- テスト方針（2026-09-27 確定）:
  - `mise run gate` と PR CI は `mock` モードで実行し、Docker を使わずに完走する（Req 1.11）。データベース依存のテストは、インプロセス DB で実行できるものに限って gate に含める（Req 1.12）
  - 各モジュールの自動テストは `mock` で完走できる。比較・品質評価のテスト（精度比較、RAG 品質評価、Capability 評価、LLM-as-a-Judge）は、`local` モードで実行可能な場合に限り実行し、実行できない場合はスキップとして報告する（Req 1.13、Req 1.14）
  - モジュールの実行（ハンズオン）自体は、`local` / `live` を原則とする（Req 2.12、Req 7.5）
- 未決: 既定の実 API プロバイダ、Evals の実行頻度と予算上限（設計フェーズで決定）

## Requirements

### Requirement 1: モノレポ基盤と品質ゲート

学習者として、1コマンドでセットアップと品質検証ができるモノレポが欲しい。これにより全モジュールを同じ規約・同じ検証手段で進められる。（モジュール 1-1）

**Acceptance Criteria**

1.1 THE プラットフォーム SHALL Web アプリ、エージェント基盤ライブラリ、評価スイートを単一リポジトリ内の独立したワークスペースパッケージとして提供する。
1.2 THE プラットフォーム SHALL エージェント基盤ライブラリを UI フレームワークに依存せず、Web アプリ以外（テスト、CLI スクリプト）からも import 可能な形で提供する。
1.3 WHEN 学習者がクリーンな clone に対して依存インストールを実行した時、THE プラットフォーム SHALL `mise.toml` に固定されたランタイム・パッケージマネージャのバージョンで全ワークスペースの依存を解決する。
1.4 WHEN 学習者が `mise run gate` を実行した時、THE プラットフォーム SHALL lint、format チェック、typecheck、テストを全ワークスペースに対して実行し、いずれかが失敗した場合は非ゼロの終了コードを返す。
1.5 WHILE 環境変数に LLM・外部サービスの API キーが一切設定されていない状態、THE プラットフォーム SHALL `mise run gate` を成功させる。
1.6 THE プラットフォーム SHALL lint / format 規約として、2スペースインデント、行幅100、シングルクォート、セミコロン必須、未使用変数・未使用 import をエラーとするルールを適用する。
1.7 WHEN プルリクエストが作成または更新された時、THE プラットフォーム SHALL CI 上で品質ゲートと同等の検証を実行し、結果をプルリクエストのステータスとして報告する。
1.8 WHEN 学習者がローカル依存サービスの起動コマンドを実行した時、THE プラットフォーム SHALL Postgres（pgvector 有効）とトレース収集基盤をコンテナとして起動する。
1.9 IF 必須の環境変数が不足した状態で Web アプリまたはエージェントを起動した場合、THEN THE プラットフォーム SHALL 不足している変数名と、それを必要とする機能名を示すエラーメッセージを出力する。
1.10 THE プラットフォーム SHALL API キー等の秘密情報をサーバー側でのみ参照し、ブラウザへ配信されるバンドルに含めない。
1.11 WHEN 学習者が `mise run gate` を実行した時、THE プラットフォーム SHALL Docker などのコンテナ実行環境を起動せずに完走する。
1.12 THE プラットフォーム SHALL データベースに依存するテストを、インプロセスのデータベース（例: pgvector 拡張を持つ組み込み Postgres 互換 DB）で実行できる場合に限り品質ゲートに含め、実行できないテストは品質ゲートとは別のタスクに分けて、品質ゲートの結果に「未実行」として件数を表示する。
1.13 THE プラットフォーム SHALL 各モジュールの自動テストを `mock` モードで完走できるようにする。比較・品質評価のテスト（検索手法の精度比較、RAG 品質評価、Capability 評価、LLM-as-a-Judge 等）はテスト名またはタグで区別し、`local` モードで実行可能な場合（Ollama に接続でき、必要なモデルが取得済み）に限り実行する。
1.14 IF 比較・品質評価のテストが `local` モードで実行できない場合、THEN THE プラットフォーム SHALL そのテストをスキップ理由付きで「スキップ」として報告し、合格として数えない。
1.15 THE プラットフォーム SHALL 品質ゲートの各段階（lint、typecheck、テスト、評価）で、実行したテスト数または走査したファイル数が 0 の場合に失敗させる（空振りの合格を防ぐ）。
1.16 THE プラットフォーム SHALL 品質ゲートに含める `mock` モードのエージェントのテストと回帰評価について、エージェントの制御ロジック（ツール選択、停止条件、検証処理）を意図的に壊した変更に対してテストが失敗することを確認する手段を提供する。

### Requirement 2: LLM プロバイダと実行モード

学習者として、同じコードのまま LLM の呼び出し先をモック・ローカル・商用 API の間で切り替えたい。これによりコストをかけずに開発・テストし、必要な時だけ実モデルで確認できる。

**Acceptance Criteria**

2.1 THE プラットフォーム SHALL 実行モードとして `mock`、`local`、`live` の3種を提供し、アプリケーションコードを変更せずに設定だけで切り替えられるようにする。
2.2 WHERE 実行モードが `live` の場合、THE プラットフォーム SHALL プロバイダとして Anthropic、OpenAI、Azure OpenAI、Google を選択可能にし、IBM watsonx.ai は AI SDK v7 に対応したプロバイダ実装が存在する場合に限り選択可能にする。
2.10 IF IBM watsonx.ai 用の AI SDK v7 対応プロバイダ実装が存在しない場合、THEN THE プラットフォーム SHALL watsonx.ai をプロバイダ選択肢と設定項目から除外し、スキップした旨と理由を解説ドキュメントに記載する。
2.11 WHILE テストランナーから実行されている状態、THE プラットフォーム SHALL モックされていない外部へのネットワーク接続（名前解決を含む）を即座に失敗させ、接続先を含むエラーでテストを失敗させる。
2.12 THE プラットフォーム SHALL Web アプリとハンズオンの既定の実行モードを `local` とし、`live` は設定で選択できるようにする。`mock` は、テストと、学習者が明示的に指定した場合にのみ使う。
2.13 WHEN 学習者が録画モードで `local` または `live` を実行した時、THE プラットフォーム SHALL LLM・外部サービスの要求と応答の組をカセットファイルに記録し、API キー等の秘密情報を記録から除外する。
2.14 IF `mock` モードで要求に一致するシナリオまたはカセットが存在しない場合、THEN THE プラットフォーム SHALL ネットワークへフォールバックせず、不足しているシナリオを示すエラーを返す。
2.15 THE プラットフォーム SHALL 外部サービス（Web ページ取得、YouTube 字幕、arXiv、Web 検索、Rerank、E2B、MCP サーバー）を、`mock` モードでは fixture または疑似実装に置き換える。
2.16 WHERE 実行モードが `mock` の場合、THE プラットフォーム SHALL 埋め込みベクトルを入力テキストから決定論的に導出したダミーベクトルとして返し、解説ドキュメントに検索精度の評価には使えないことを明記する。
2.3 WHERE 実行モードが `local` の場合、THE プラットフォーム SHALL ローカルで稼働する Ollama サーバー上のモデルへ LLM 呼び出しを送る。
2.4 WHERE 実行モードが `mock` の場合、THE プラットフォーム SHALL ネットワーク通信を行わず、(a) モジュールごとに定義したシナリオスクリプト、または (b) `local` / `live` モードで録画した応答（カセット）の再生によって、テキスト、構造化オブジェクト、ツール呼び出し、ストリームチャンクを同一入力に対して毎回同一の内容で返す。
2.5 WHILE テストランナーから実行されている状態、THE プラットフォーム SHALL 明示的な上書き設定がない限り実行モードを `mock` とする。
2.6 IF 選択されたプロバイダの認証情報が未設定の場合、THEN THE プラットフォーム SHALL LLM 呼び出しを行わずに、プロバイダ名と必要な環境変数名を含むエラーを返す。
2.7 IF 実行モードが `local` で Ollama サーバーに接続できない場合、THEN THE プラットフォーム SHALL 接続先 URL と起動方法の案内を含むエラーを返す。
2.8 THE プラットフォーム SHALL 用途（チャット、構造化出力、埋め込み、評価器）ごとに使用するモデルを設定で指定できるようにし、モデル ID をアプリケーションコードにハードコードしない。
2.9 IF 選択されたモデルが要求された機能（ツール呼び出し、構造化出力、推論トークン、埋め込み）に対応していない場合、THEN THE プラットフォーム SHALL 呼び出し前に、非対応の機能名とモデル名を含むエラーを返す。

### Requirement 3: ストリーミングチャット

学習者として、ブラウザ上でモデルを切り替えながらリアルタイムにストリーミングされるチャットを試したい。（モジュール 1-2）

**Acceptance Criteria**

3.1 WHEN 学習者がチャット画面でメッセージを送信した時、THE プラットフォーム SHALL 応答テキストを生成完了を待たずにトークン単位で逐次表示する。
3.2 THE プラットフォーム SHALL チャット画面で、実行モードとプロバイダの組み合わせから利用可能なモデルの一覧を表示し、学習者が選択できるようにする。
3.3 WHEN 学習者が会話途中でモデルを切り替えた時、THE プラットフォーム SHALL 既存の会話履歴を保持したまま、次のメッセージから新しいモデルで応答を生成する。
3.4 WHERE 選択されたモデルが推論トークン（思考過程）を出力する場合、THE プラットフォーム SHALL 推論内容を最終回答とは視覚的に区別された折りたたみ可能な領域に表示する。
3.5 WHEN 学習者が生成中に停止操作を行った時、THE プラットフォーム SHALL ストリーミングを中断し、それまでに受信したテキストを会話履歴に保持する。
3.6 IF LLM 呼び出しがエラーで失敗した場合、THEN THE プラットフォーム SHALL チャット画面にエラー内容と再送操作を表示し、送信済みの学習者メッセージを失わない。
3.7 THE プラットフォーム SHALL 各応答について、使用したモデル名と入力・出力トークン数を表示する。
3.8 THE プラットフォーム SHALL LLM 呼び出しをサーバー側で実行し、ブラウザから直接 LLM プロバイダへ通信しない。
3.9 WHERE 選択されたモデルが画像入力に対応している場合、THE プラットフォーム SHALL 学習者がチャットに画像を添付して送信し、画像の内容に基づく応答を得られるようにする。
3.10 THE プラットフォーム SHALL システムプロンプト（ペルソナ）を、バージョン管理されたテンプレートとして複数提供し、学習者がチャット画面で切り替えられるようにする。
3.11 WHILE 実行モードが `live` の状態、THE プラットフォーム SHALL LLM を呼び出す前に、リクエストの件数・長さ・サイズの上限と単位時間あたりの呼び出し回数の上限を検査し、超過したリクエストを LLM 呼び出しなしで拒否する。

### Requirement 4: 構造化出力と要約パイプライン

学習者として、Web 記事や動画字幕から型安全な要約を抽出し、UI にカードとして描画したい。正規表現パースに頼らないスキーマ駆動開発とプロンプトキャッシュを体験する。（モジュール 1-3）

**Acceptance Criteria**

4.1 WHEN 学習者が Web 記事の URL を入力した時、THE プラットフォーム SHALL 本文テキストを取得し、タイトル、3行の要点、重要タグ、アクション項目を持つ要約オブジェクトを生成する。
4.2 WHEN 学習者が動画の字幕テキスト（トランスクリプト）を入力した時、THE プラットフォーム SHALL 4.1 と同じ構造の要約オブジェクトを生成する。
4.3 THE プラットフォーム SHALL 要約オブジェクトをスキーマで検証し、スキーマに適合したオブジェクトのみを UI とライブラリ利用者へ返す。
4.4 IF LLM の出力がスキーマ検証に失敗した場合、THEN THE プラットフォーム SHALL 最大2回まで再生成し、それでも失敗した場合は検証エラーの内容を含むエラーを返す。
4.5 WHILE 要約オブジェクトを生成中の状態、THE プラットフォーム SHALL 確定したフィールドから順にカード UI へ逐次描画する。
4.6 WHEN 入力テキストが選択モデルのコンテキスト上限を超える長さである時、THE プラットフォーム SHALL 入力を分割して段階的に要約し、最終的に 4.1 と同じ構造の要約オブジェクトを1つ返す。入力がコンテキスト上限内に収まる場合は、分割せずに全文を1回の呼び出しで要約する。
4.7 IF 指定 URL の取得に失敗した場合、または本文が空の場合、THEN THE プラットフォーム SHALL LLM を呼び出さずに、失敗理由（HTTP ステータスまたは空本文）を含むエラーを表示する。
4.8 WHERE 選択プロバイダがプロンプトキャッシュに対応している場合、THE プラットフォーム SHALL 同一の長いコンテキストを再送する呼び出しでキャッシュを有効化し、キャッシュ読み出しトークン数を記録・表示する。
4.9 WHEN 学習者が YouTube 動画の URL を入力した時、THE プラットフォーム SHALL 動画の字幕（トランスクリプト）をタイムスタンプ付きで取得し、4.2 の入力として要約する。
4.10 WHEN タイムスタンプ付きの字幕から要約を生成した時、THE プラットフォーム SHALL 要約オブジェクトに、各見出しと開始時刻を持つ目次（チャプター）を含める。
4.11 IF 指定動画の字幕が取得できない場合（字幕なし、非公開、取得エラー）、THEN THE プラットフォーム SHALL LLM を呼び出さずに、取得できなかった理由を含むエラーを表示する。
4.12 THE プラットフォーム SHALL 各要約について、分割せずに全文を投入したか、分割して段階的に要約したかと、その判断に用いた入力トークン数を結果に含める。

### Requirement 5: ツール呼び出しと ToolLoopAgent

学習者として、受動的な生成からツールを使う AI エージェントへの転換を、AI SDK v7 の `ToolLoopAgent` で最小構成から体験したい。ツールの実行状況と結果が UI 上で型付きのコンポーネントとして見えるようにしたい。（モジュール 1-2）

**Acceptance Criteria**

5.1 WHEN 学習者がツールを必要とする質問を送信した時、THE プラットフォーム SHALL `ToolLoopAgent` により「ツール呼び出し → 結果の取得 → 次の判断」を停止条件（Req 6）に達するか回答が完成するまで反復し、最終回答をストリーミングで返す。
5.2 THE プラットフォーム SHALL 外部 API キーなしで動くサンプルツール（現在時刻、計算、為替換算、天気）を提供する。
5.3 WHERE Web 検索サービスの API キーが設定されている場合、THE プラットフォーム SHALL Web 検索ツールをエージェントに登録する。
5.4 IF Web 検索サービスの API キーが未設定の場合、THEN THE プラットフォーム SHALL Web 検索ツールを登録せず、UI に無効である旨と有効化に必要な設定を表示する。
5.5 WHEN ツールの実行が開始・完了・失敗した時、THE プラットフォーム SHALL チャット画面に、ツール名、入力、実行状態、結果を表示する。表示用コンポーネントが登録されたツールの結果は、生の JSON ではなく、型付きの UI コンポーネント（カード、チャート、フォーム等）として描画する（Generative UI）。
5.6 WHILE 質問がモデル自身の知識だけで回答できる状態、THE プラットフォーム SHALL ツールを呼び出さずに回答できるようにし、各回答で呼び出したツールの一覧を結果に含める。
5.7 THE プラットフォーム SHALL 現在時刻に依存するツールに、時刻を取得する関数（Clock）を注入し、ツール内で直接システム時刻を読まない。
5.8 IF ツールの実行中に例外が発生した場合、THEN THE プラットフォーム SHALL ループを中断せず、エラー内容をツール結果としてエージェントに返す（003 Req 1.3 の形式に従う）。

### Requirement 6: ループ制御と強制停止条件

学習者として、エージェントの無限ループや暴走を物理的に遮断し、なぜ止まったのかを後から確認できるようにしたい。（全体。M1 から適用し、モジュール 4-4 で解説）

**Acceptance Criteria**

6.1 THE プラットフォーム SHALL すべての `ToolLoopAgent` に、最大ステップ数、累積トークン使用量の上限、実行時間の上限の3種の停止条件を設定し、いずれかに達した時点でループを停止する。既定値は設定で変更できる。トークン上限と実行時間上限の判定はステップの完了時に行う近似であり、上限を超えたステップは完了まで実行されることを解説ドキュメントに明記する。
6.2 WHEN エージェントループが停止した時、THE プラットフォーム SHALL 停止理由を閉じた語彙（`completed`、`step-limit`、`token-budget`、`timeout`、`aborted`、`error`）の1つとして実行結果に含める。
6.3 WHEN 学習者が実行中のエージェントを停止した時、THE プラットフォーム SHALL 停止を実行中の LLM 呼び出し、ツール実行、サンドボックスへ伝播させて中断し、停止理由を `aborted` とする。
6.4 IF 1回のツール実行が設定された時間上限を超えた場合、THEN THE プラットフォーム SHALL そのツール実行を打ち切り、タイムアウトしたことをツール結果としてエージェントに返してループを継続する。
6.5 THE プラットフォーム SHALL 停止理由と、停止時点のステップ数・累積トークン数・経過時間を、トレース（004 Req 5）と評価レポート（004 Req 3.10）に記録する。

## Non-Functional Requirements

本節の非機能要件は、spec 001〜004 のすべてに適用する。

- **検証速度**: WHILE 実行モードが `mock` の状態、THE プラットフォーム SHALL 依存インストール済みの開発機で `mise run gate` を 5 分以内に完了する。
- **決定性**: WHILE 実行モードが `mock` の状態、THE プラットフォーム SHALL 同一コミットに対して品質ゲートを 10 回連続実行した場合に 10 回とも同一の合否結果を返す。
- **オフライン動作**: WHILE ネットワークに接続されていない状態、THE プラットフォーム SHALL `mock` モードでの品質ゲートを実行可能にする（依存インストールを除く）。
- **ストリーミング応答性**: THE プラットフォーム SHALL `mock` モードにおいて、チャット送信から最初のトークンが画面に表示されるまでを 500 ms 以内とする。
- **型安全性**: THE プラットフォーム SHALL TypeScript の strict モードで型検査を通し、エージェント基盤ライブラリの公開 API に `any` 型を含めない。
- **テストカバレッジ**: THE プラットフォーム SHALL エージェント基盤ライブラリの行カバレッジを 80% 以上に保つ。
- **秘密情報**: THE プラットフォーム SHALL API キーを環境変数からのみ読み込み、秘密情報を含む設定ファイルをバージョン管理の対象から除外し、キー名の一覧のみを含むサンプル設定ファイルを提供する。
- **隔離実行**: THE プラットフォーム SHALL LLM が生成したコード（データ分析のコード、長時間実行ハーネスの実装コードと検証テストスクリプトを含む）をホスト環境で実行せず、サンドボックスまたはコンテナ内でのみ実行する（003 Req 3.2、004 Req 2.10 の横断適用）。
- **アクセシビリティ**: THE プラットフォーム SHALL チャット画面、ダッシュボード、承認ダイアログをキーボードのみで操作可能にし、WCAG 2.2 AA のコントラスト基準を満たす。
- **対応ブラウザ**: THE プラットフォーム SHALL 最新安定版の Chrome、Firefox、Safari で Web アプリの全機能を動作させる。
- **UI 言語**: THE プラットフォーム SHALL Web アプリの UI 文言と解説ドキュメントを日本語で提供する。
- **コスト可視化**: WHERE 実行モードが `live` の場合、THE プラットフォーム SHALL 評価レポートとトレースに、トークン使用量に基づく推定コストを表示する。
