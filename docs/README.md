# モジュール解説ドキュメント

「From GenAI to Agentic AI」の学習者向け解説です。カリキュラム（[specs/curriculum/](../specs/curriculum/README.md)）が「何を、どの順序で学ぶか」を定め、この `docs/` が「各モジュールで何を読み、何を作り、どう習熟を確かめるか」を説明します。

要件の正本は [spec 001](../specs/001-agentic-ai-platform/spec.md)（Requirement 7）です。この文書と食い違う場合は spec が正です。

## 構成

| パス | 内容 |
|---|---|
| [modules/index.md](modules/index.md) | 19 モジュールの一覧と、解説の状態 |
| [phases/phase-1.md](phases/phase-1.md) | Phase 1 が扱う IBM 成熟度モデルの水準と学習の流れ |
| `modules/<phase>-<n>-<name>.md` | 各モジュールの解説。ファイル名の先頭 `1-2` がモジュール番号 |
| [modules/_template.md](modules/_template.md) | 19 モジュール共通の解説テンプレート |

Phase 1（モジュール 1-0〜1-3）はマイルストーン 1 で提供します。2-1 以降は、各マイルストーンの spec が承認され、実装が完了した時点で同じテンプレートに沿って追加します。

## 読み方

1. [modules/index.md](modules/index.md) で、読みたいモジュールの状態を確かめます。
2. 各解説は、学習目標 → 主要トピック → ハンズオン手順 → 習熟度判定チェックリスト の順に読み進めます。
3. ハンズオンは手元のリポジトリで実行します。`mock` で通る手順はキーなしで確かめられ、`local` / `live` の手順は準備が必要です。
4. 完成時点のタグ（`module/<phase>-<n>`）と自分の作業を `git diff` で比べると、つまずいた箇所に戻れます。

## 実行モードと外部サービスの表記

ハンズオンの各手順は、必要な実行モードと外部サービスを明記します（Req 7.5）。

| 表記 | 意味 | 必要なもの |
|---|---|---|
| `mock` | 決定論的な固定応答で動く。品質ゲートとテストの既定 | なし（ネットワークも不要） |
| `local` | Ollama のローカルモデルで動く。ハンズオンの既定 | Ollama の起動とモデルの取得 |
| `live` | 商用 API で動く | プロバイダの API キー（環境変数） |

外部サービスの欄には、API キー名、Docker、Ollama などを書きます。不要な場合は「なし」と書きます。`mock` は挙動の確認に向きますが、モデルの品質や検索精度の評価には使えません。

## モデルの書き方

解説にモデル ID（プロバイダのモデル名）は書きません。使うモデルは、モデルカタログ（`packages/ai-core/src/models/catalog.ts`）への参照で示します。

```text
catalog: live.anthropic.chat
```

モデル ID の文字列は `mise run check:model-ids` が解説の本文からも検出します。

## 習熟度チェックリストとテストの参照

習熟度判定チェックリストの項目のうち、自動テストで確かめられるものには、HTML コメントでテストへの参照を付けます。

```markdown
- [ ] 停止条件に達するとループが止まる <!-- test: packages/ai-core/src/agents/stop-reason.test.ts#derives the stop reason -->
```

書式は `<!-- test: <リポジトリ相対のパス>#<テスト名> -->` です。

- **テスト名は固定の文字列にします。** `describe` / `it` / `test`（`describeLocal` / `itLocal` を含む）の第1引数の文字列リテラルを、静的に抜き出して照合します。`it.each` やテンプレートリテラルで名前を組み立てたテストは、参照先にできません。
- 参照先のファイルと名前が実在しなければ、`mise run docs:check` が失敗します。走査した参照が 0 件でも失敗します。
- 手で確かめる項目は、参照なしのチェック項目として書きます。

## 必須の節と話題

`mise run docs:check`（`scripts/check-docs.mjs`）は、各解説について次を検査します。

- [テンプレート](modules/_template.md)の必須の節がそろっていること。Phase 1 の解説は Python / Streamlit 経験者向けコラムも必須です。
- spec 001 Requirement 7.9 の表で、そのモジュールに割り当てられた必須トピックが、**見出し**として存在すること。見出しには、トピックの文言をそのまま含めます。
- ハンズオンの各手順（`### 手順 N: …`）に、`実行モード:` と `外部サービス:` の行があること。
- 元教材との対照表に「移植で諦めたもの」の列があること。
- 習熟度チェックリストのテスト参照が実在すること。

`docs:check` は品質ゲート（`mise run gate`）の最後の段です。

## 完成時点のタグ

モジュールのリファレンス実装が完成した時点を、注釈付きタグ `module/1-1`、`module/1-2`、`module/1-3` として提供します（1-0 は解説のみのためタグはありません）。タグが指すコミットには、並列に進めた他モジュールの途中の実装が含まれることがあり、E2E テストと解説は含まれません。各解説の「完成時点のタグ」の節に、含まれるものと含まれないものを書きます。

## 言語
