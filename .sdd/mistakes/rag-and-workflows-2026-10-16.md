# hydration より先に着地した fill が送信ボタンを有効にしない（M2 W5 の E2E）

## 何が起きたか

- M2 の PR #39 は、ローカルの E2E 363 件と CI の全ジョブが成功してマージされた。その後、main の CI が #40 と #41 で WebKit を中心に赤くなった。
- フォームの `fill` が hydration より先に着地すると、React が追跡する値と、入力欄の値が一致したままになる。再入力しても、値が同じなら input イベントが無視され、送信ボタンが有効にならなかった。
- #40 の「有効になるまで再入力」だけでは直らなかった。

## 根本原因

1. React は、追跡している値と同じ値の input イベントを無視する。入力欄を空にせずに同じ値を再入力しても、変更として見えない。
2. 入力が hydration より先に着地するタイミングを、意図的に再現するテストがなかった。CI の緑は、タイミングが合っただけだった可能性が高い（推測）。
3. 失敗時に trace や console が CI に残らず、原因が特定できなかった（#41 で追加）。

## 影響

main の CI が、#39 のマージ（10:34）から #42 のマージ（13:01）まで約 2.5 時間赤かった。製品のコードの欠陥ではなく、テストの欠陥。

## 防止策

- 再入力の前に入力欄を空にする（`apps/web/e2e/support/form.ts`）。
- スクリプトの配信を遅らせて、hydration より先の fill を再現する回帰テストを持つ（`apps/web/e2e/hydration.spec.ts`）。
- E2E が失敗したら Playwright の trace を CI の成果物に保存する（#41）。
- 「PR の CI が緑」を「タイミングに依存する欠陥がない」とは読まない。
