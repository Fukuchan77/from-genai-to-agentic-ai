# Product

本プロダクトの目的と価値を記す永続知識。機能の一覧ではなく、判断の拠り所を書く。
個別の要件と数値の正本は `specs/00N-*/spec.md`（横断制約・NFR は `001`）にある。

## Purpose

「From GenAI to Agentic AI」は、Python / LangChain / LangGraph で LLM アプリを学んだ（学ぼうと
している）エンジニアが、TypeScript / Web 標準スタックで本番品質の Agentic AI システムを一人で
設計・構築・評価できるようになるための**カリキュラムとそのリファレンス実装**である。

3冊の Python 教材（LLM アプリ入門、RAG・エージェント設計パターン、実践エージェント）と
Anthropic / IBM の Agentic AI の知見を、Next.js + Vercel AI SDK v7 + Zod + MCP + E2B + Vitest へ
移植・統合する。

## Users & Value

| 学習者の背景 | Need | Value delivered |
|----------------|------|-----------------|
| Python / LangChain 経験のある学習者 | TS スタックでエージェントを作れるようになる | 元教材との対照表付きで、同じ題材を TS で再実装できる |
| エージェントを本番に出したいエンジニア | 暴走しない・評価できる・安全なエージェントの作り方 | 停止条件、Evals、承認ゲート、サンドボックスを実装とテストで示す |
| 独習者（1人・ローカル） | API キーなしでも手を動かせる | `mock` で全テストが決定論的に通り、`local`（Ollama）でハンズオンできる |

利用者は「学習者」1人だけである（001 Glossary）。表の行は別々のペルソナではなく、学習者が持ち込む
背景と動機の違いを示す。

価値は次の3点に集約される（001 spec Overview）。

1. 受動的生成 → タスク自動化 → 自律型エージェントへの成熟段階を、コードで体験できる。
2. API キーなしでも全テストが決定論的に通る。
3. 各モジュールの習熟度を、チェックリストと自動テストで客観的に判定できる。

## Core Capabilities

カリキュラムは 4 フェーズ・19 モジュールで、マイルストーン単位の spec に分かれる。

| Milestone | spec | 内容 |
|-----------|------|------|
| M1 | `001-agentic-ai-platform` | 基盤（モノレポ、品質ゲート、実行モード）、ストリーミングチャット、ToolLoopAgent とGenerative UI、構造化要約 |
| M2 | `002-rag-and-workflows` | TS ネイティブ RAG（pgvector + Drizzle）、Advanced RAG（HyDE / Multi-Query / RRF / Rerank）、5大ワークフローパターン、デザインパターン |
| M3 | `003-domain-agents` | ACI / MCP、ヘルプデスク、データ分析（E2B）、論文リサーチ、要件定義書生成、マーケティング |
| M4 | `004-harness-evals-safety` | コンテキストエンジニアリング、長時間実行ハーネス、Agent Evals、安全設計、総合演習 |
| 横断 | `005-hub-alignment` | 統合ハブ `vaz-agentic-ai-next` との役割分担: 002〜004 の本番実装との境界、解説からハブの手法ページへのリンク検査、承認ダイアログの UI 部品とテーマトークンの共有（002 の要件承認より前に承認） |

各モジュールは次の3点を揃えて完成とする。

- **リファレンス実装** — 動くコード（`packages/ai-core` のロジック + `apps/web` の画面）
- **テスト** — `mock` で完走し、制御ロジックを壊すと落ちる
- **日本語の解説** — 学習目標、ハンズオン手順、習熟度チェックリスト（テスト参照付き）、元教材との対照表

## Product Principles

- **ワークフローとエージェントを峻別して教える** — 制御フローをコードが決めるならワークフロー、
  LLM が決めるならエージェント。実装が両者を混ぜると、教材が誤った設計を教える。
- **エージェントは必ず止まり、止まった理由を語る** — ステップ数・累積トークン・実行時間の3種の
  停止条件と、閉じた語彙の停止理由を全エージェントに持たせる。
- **緑は本物であること** — テスト 0 件や全件スキップを合格にしない。空振りの緑は壊れた教材を
  合格させる。
- **被害範囲を最小にする** — LLM 生成コードはホストで実行しない。書き込み・破壊的ツールは承認
  ゲートの実装後にだけ登録する。
- **事実は実測で確定する** — API・版・モデル ID は元教材の記述や記憶ではなく、公式ドキュメントと実測で
  確かめる。移植時の変更点は解説に明記する。
- **段階ゲートを飛ばさない** — M1 → M4 の順に進め、後続 spec の要件は先行マイルストーンの実装後に
  人間が承認する。

## Out of Scope

- 認証・認可、マルチテナント、ロールベース権限（学習者1人のローカル実行が前提）
- 本番デプロイ手順（任意扱い）
- 会話履歴の永続化、分散レート制限
- LangChain / LangGraph の抽象の持ち込み（移植で失われた機能は解説の対照表に記録する）
- IBM watsonx.ai（AI SDK v7 対応のプロバイダ実装が出るまでスキップ）
