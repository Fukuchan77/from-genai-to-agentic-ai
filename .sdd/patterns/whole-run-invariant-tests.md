# 全体の不変条件のテスト

## Problem

変異スタブ（PROVE）を 1 行ずつ殺しても、「実行全体で成り立つべき規則」は検出できない。003 では、約 700 本のスタブを殺した後でも、レビューが毎波、全体の欠陥を見つけた。例は共有予算が上限として働かない（W5 F-1、W6 で 330/100、W8 F-1）、二重送信でラウンドが 2 回閉じる（W6）、mock の Web アプリが FAQ を取り込まず全問合せが escalate される（W7 F-1）。どの 1 行も規則を破っておらず、実サーバー E2E も途中の形（`T-` や `改訂 1`）しか確認していなかった。

## Solution

機能ごとに、「規則」と「実行の終端状態」を 1 つずつ文で書き、実際の実行（mock の run 全体）がそれを満たすことを主張するテストを置く。スタブ単位のテストと区別し、実装前に書く。

## Implementation

- 予算なら「run の合計 ≤ `maxTotalTokens`」。上限として使えないなら、その事実をテストと解説に書く（W8 の決定: ソフトな上限）。
- 状態遷移なら「二重送信しても閉じるラウンドは 1 回」。
- E2E なら途中の形ではなく結果を見る（問合せが escalate されず、根拠つきで解決する）。
- 持ち越し項目（別のタスクへ回した検査）は、受け側のタスクの `_Requirements:_` に書き、完了にする前に実在を確認する。
- 修正の担当者が PROVE を実行したと報告しても、主セッションで再実行する（W7 で 6 件中 3 件が未実行だった）。

## Benefits

- スタブでは見えない「どの行も破っていないのに規則が破れる」欠陥を、レビューの前に見つけられる。
- 規則を満たせないとき、直すのか、上限の定義を変えるのかを、人が決める材料になる。
